# تصویرهای مرکز آموزش دوفیکسو

اسکرین‌شات‌های قدم‌به‌قدم آموزش‌ها و کاور مقاله‌ها، از اجرای واقعی اپ روی
داده‌ی یک تعمیرگاه موبایل ساختگی: **«موبایل‌کده نگین»**. فاز ۱۳ رودمپ، اسپرینت
13C. مقاله‌ها خودشان در ریپوی لندینگ‌اند (`src/content/academy/`).

چرا اسکریپت و نه عکس دستی: UI عوض می‌شود. با اسکریپت، تازه کردن همه‌ی
تصویرها یک دستور است؛ با عکس دستی، شش ماه بعد نصف آموزش‌ها عکس قدیمی دارند.

## داده‌ی دمو

- مغازه‌ی موبایل ساختگی در اصفهان، ورود با `09121234567` / `Demo@12345`
- ۵ نفر پرسنل (مدیر کل، مدیر، سه تعمیرکار)، ۳۶ مشتری، ۵۸ دستگاه (گوشی و تبلت
  سامسونگ، آیفون، شیائومی) در همه‌ی وضعیت‌ها
- ۲۱ کالا در پنج دسته (ال‌سی‌دی و تاچ، باتری، سوکت و قطعات برد، لوازم جانبی،
  مصرفی)، ۱۳ فاکتور خرید با قیمت‌های کمی متفاوت تا قیمت تمام‌شده‌ی میانگین
  موزون واقعاً حرکت کند، حدود ۳۰ فاکتور فروش و تعمیر در چهار ماه
- کیف پول پیامکی با تاریخچه‌ی پیامک‌های ارسالی

⚠️ **هیچ داده‌ی واقعی.** شماره‌ها عمداً پشت‌سرهم‌اند (`091234567xx`): شماره‌ی
تصادفی ممکن است مال یک آدم واقعی باشد و در تصویری که منتشر می‌شود بیاید.
داده تکرارپذیر است — همان seed همیشه همان داده را می‌سازد.

## راه‌اندازی، یک بار

1. اپ را مثل همیشه بالا بیاورید (`README.md` اصلی ریپو)، با یک پایگاه‌داده‌ی
   **تازه**، و در `backend/.env`:
   ```
   SEED_ADMIN_USERNAME=09121234567
   SEED_ADMIN_PASSWORD=Demo@12345
   RATE_LIMIT_LOGIN=0
   ```
   ⚠️ **`SMS_API_KEY` را یک مقدار ساختگی بگذارید** (مثلاً `local-demo`).
   `fix-dates.sql` پیامک به مشتری را برای workspace دمو روشن می‌کند؛ با کلید
   واقعی sms.ir، ثبت یا تغییر وضعیت یک دستگاه — مثلاً هنگام ضبط ویدیو — پیامک
   واقعی به شماره‌های دمو می‌فرستد، که ممکن است مال آدم‌های واقعی باشند. با
   کلید ساختگی، ارسال شکست می‌خورد و هزینه به کیف پول دمو برمی‌گردد.

   فرانت روی `http://localhost:5173` — نه `127.0.0.1`؛ کوکی refresh با
   SameSite=Strict بین این دو فرستاده نمی‌شود.

   اپ بدون S3 بالا نمی‌آید. اگر نمی‌خواهید به باکت واقعی وصل شوید، یک S3
   محلی کافی است:
   ```bash
   python3 -m venv .venv && .venv/bin/pip install 'moto[server]'
   .venv/bin/moto_server -H 127.0.0.1 -p 9000 &
   # و در backend/.env:
   # S3_ENDPOINT=http://127.0.0.1:9000  S3_BUCKET=dofixo-demo
   # S3_ACCESS_KEY=demo  S3_SECRET_KEY=demo  S3_REGION=us-east-1
   # باکت را یک بار بسازید (با boto3 همان venv یا aws cli)
   ```

2. داده:
   ```bash
   cd docs/academy
   pnpm install
   npx playwright install chromium     # اگر مرورگر Playwright ندارید
   pnpm data
   psql "$DATABASE_URL" -f fix-dates.sql   # اتصال مالک (dofixo)، فقط یک بار
   ```

## ساختن تصویرها

```bash
pnpm images                       # همه: اسکرین‌شات‌ها و بعد کاورها
pnpm shots device-intake          # فقط یک آموزش
pnpm covers tutorials/device-intake
pnpm downloads                    # فرم‌های قابل دانلود: HTML ← PDF
```

- اسکرین‌شات‌ها: `out/shots/<آموزش>/<nn-name>.webp` — ۱۴۴۰ پیکسل، تم روشن،
  با کادر و شماره‌ی نارنجی روی جایی که باید کلیک کرد.
- کاورها: `out/covers/<section>/<slug>/cover.webp` — ۱۲۰۰×۶۳۰، همان تصویر
  اشتراک‌گذاری. همان مسیری است که مقاله در لندینگ دارد.
- فرم‌ها: `downloads/<name>.html` ← `out/downloads/<name>.pdf`، که در لندینگ به
  `public/downloads/` می‌رود، و پیش‌نمایشش `out/shots/downloads/<name>.webp`
  (تصویر مقاله و کاور).
- `out/` در گیت نیست؛ تصویرها در ریپوی لندینگ، کنار مقاله، کامیت می‌شوند.

کاورها فونت و لوگو را از ریپوی لندینگ برمی‌دارند. اگر آن ریپو کنار این ریپو
نیست: `LANDING_DIR=/path/to/dofixo-landing pnpm covers`.

مرورگر Playwright جای دیگری نصب است؟ `CHROMIUM_PATH=/path/to/chrome`.

## تصویرهای صفحه‌ی اول سایت

`pnpm shots site` — گالری «اسکرین‌شات‌ها»، تصویر هر ماژول در بخش «از پراکندگی
به نظم» و تصویر hero. با تراکم دو برابر (۲۸۸۰ پیکسل)، چون در لایت‌باکس
تمام‌صفحه باز می‌شوند، و بدون کادر و شماره.

- `out/shots/site/*.webp` (جز `*-mobile` که فقط در hero به کار می‌روند) ← لندینگ `src/assets/site/` (فهرست و توضیح هر تصویر:
  `src/data/appScreens.ts`)
- `out/shots/site/hero.webp` ← لندینگ `public/images/hero-img.webp`. ترکیبش در
  `site/hero.html` است: فهرست دستگاه‌ها در قاب مرورگر و داشبورد در قاب گوشی،
  با پس‌زمینه‌ی شفاف. سایه‌ها باید پیش از لبه‌ی تصویر محو شوند، وگرنه روی سایت
  یک مستطیل کم‌رنگ دیده می‌شود.

## افزودن آموزش تازه

1. `shots/tutorials/<slug>.mjs` — یک تابع که با `session()` وارد می‌شود، صفحه
   را قدم‌به‌قدم جلو می‌برد و برای هر قدم `mark()` و `shot()` صدا می‌زند.
   `device-intake.mjs` نمونه است.
2. نام فایل‌های خروجی همان نامی است که مقاله به آن ارجاع می‌دهد
   (`![…](./03-pick-customer.webp)`).
3. اگر کاور هم لازم است، یک ردیف به `covers/covers.json`.

**انتخاب عنصر:** با متن و placeholder خود UI (`getByRole("button", { name:
"ثبت دستگاه جدید" })`، `getByPlaceholder(…)`) — همان چیزی که مقاله به خواننده
می‌گوید. اگر متنی در UI عوض شد و اسکریپت شکست، یعنی مقاله هم باید عوض شود.

## آنچه هنوز نیست

**عکس دستگاه.** داده‌ی دمو عکس گوشی ندارد؛ تصویر ساختگی در آموزشی درباره‌ی
عکس گرفتن هنگام پذیرش گمراه‌کننده است. برای آن آموزش و مقاله‌ی «عکس هنگام
پذیرش» چند عکس واقعی از یک گوشی (بدون اطلاعات شخصی روی صفحه) لازم است.
