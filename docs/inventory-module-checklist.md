# چک‌لیست تست دستی شاخه‌ی `claude/inventory-module`

همه‌ی چیزهایی که فاز ۱۴ (۱۴.۱ تا ۱۴.۲۲) عوض کرده یا اضافه کرده، به ترتیبی که
تست کردنشان منطقی است. هر بند **رفتار مورد انتظار** را می‌گوید؛ اگر چیزی غیر از
آن دیدید، همان بند را با یک اسکرین‌شات بفرستید.

> تست‌های خودکار (۸۲۵ تست واحد، ۵۱۶ تست یکپارچه روی Postgres واقعی) همه‌ی
> قانون‌های موجودی را جدا چک می‌کنند. این چک‌لیست برای چیزهایی است که فقط
> با چشم دیده می‌شوند: متن‌ها، فرم‌ها، جریان کار، گوشی، حالت تیره.

---

## ۰. آماده‌سازی

```bash
# بکاپ از دیتابیس لوکال
docker compose exec postgres pg_dump -U dofixo -d dofixo_dev > ~/dofixo-backup-$(date +%F).sql

git fetch origin
git checkout claude/inventory-module
git pull origin claude/inventory-module

cd backend
pnpm install
pnpm exec prisma migrate deploy     # نه `pnpm migrate`
pnpm exec prisma generate
pnpm dev

# ترمینال دیگر
cd frontend
pnpm install
pnpm dev                            # http://localhost:5173
```

- [ ] `migrate deploy` بدون خطا تمام شد و آخرین مهاجرت `20261009221023_stock_transfers` است.
- [ ] با یک اکانت **مدیر کل** وارد شوید. (تکنیسین هیچ صفحه‌ی انباری نمی‌بیند — بند ۱۴.)

**داده‌ی پیشنهادی برای تست:** دو کالای «عددی» (مثلاً ال‌سی‌دی و باتری) و یک
کالای «کسری» (سیم، واحد متر). اعداد پایین بر همین فرض‌اند.

---

## ۱. کالا و موجودی اولیه (۱۴.۸، ۱۴.۱۱)

- [ ] «انبار و کالاها» ← کالای جدید: فیلدهای **قیمت فروش**، تیک **کالای کسری** و **موجودی اولیه + بهای هر واحد** دیده می‌شوند.
- [ ] موجودی اولیه بدون بها → خطای «برای موجودی اولیه، بهای خرید هر واحد الزامی است».
- [ ] ال‌سی‌دی با موجودی اولیه ۱۰ و بهای ۱٬۰۰۰٬۰۰۰ ریال ثبت شود. موجودی ۱۰، میانگین بها ۱٬۰۰۰٬۰۰۰. **هیچ فاکتور خریدی (PUR) ساخته نمی‌شود.**
- [ ] واحد «متر» را انتخاب کنید: تیک «کسری» خودش زده می‌شود. سیم با موجودی ۲۵٫۵ ثبت شود.
- [ ] در فیلد مقدار کالای عددی، نقطه‌ی اعشار پذیرفته نمی‌شود. در کالای کسری، «۲٫۵» با ارقام فارسی و «٫» پذیرفته می‌شود.
- [ ] مقادیر اعشاری همه‌جا با ارقام فارسی و «٫» نمایش داده می‌شوند (۲۵٫۵) و هرگز گرد نمی‌شوند.

## ۲. انبارها (۱۴.۱۰)

- [ ] منوی «انبارها»: یک «انبار اصلی» پیش‌فرض هست.
- [ ] **تا وقتی فقط یک انبار فعال هست، هیچ‌جا انتخابگر انبار دیده نمی‌شود** — نه در فاکتورها، نه در گزارش‌ها، نه در صفحه‌ی کالا. منوی «انتقال بین انبارها» هم نیست.
- [ ] انبار دوم بسازید («قفسه تعمیرات»). **بدون رفرش** منوی «انتقال بین انبارها» ظاهر می‌شود و فرم فاکتورها انتخابگر انبار پیدا می‌کنند.
- [ ] غیرفعال کردن انبار پیش‌فرض رد می‌شود با پیام توضیح.
- [ ] غیرفعال کردن انباری که موجودی دارد رد می‌شود و می‌گوید چند کالا در آن هست.
- [ ] انبار دیگری را پیش‌فرض کنید؛ برچسب «پیش‌فرض» جابه‌جا می‌شود. (بعد برگردانید.)
- [ ] انبار خالی را غیرفعال کنید → منوی انتقال، اگر فقط یک انبار فعال ماند، بدون رفرش ناپدید می‌شود. دوباره فعالش کنید.

## ۳. فاکتور خرید (۱۴.۵)

- [ ] خرید ۵ عدد ال‌سی‌دی به قیمت ۲٬۰۰۰٬۰۰۰ → موجودی ۱۵، میانگین بها **۱٬۳۳۳٬۳۳۳** (میانگین متحرک: ۱۰×۱م + ۵×۲م تقسیم بر ۱۵).
- [ ] با دو انبار، خرید را در «قفسه تعمیرات» ثبت کنید؛ در صفحه‌ی کالا موجودی به تفکیک انبار درست است.
- [ ] ویرایش همان فاکتور (۵ → ۳): موجودی و میانگین درست برمی‌گردند.
- [ ] **حذف یا کم کردن خریدی که کالایش فروخته شده رد می‌شود** با پیام فارسی (قبلاً بی‌صدا موجودی را صفر می‌کرد).

## ۴. فاکتور فروش (۱۴.۶)

- [ ] قیمت پیش‌فرض هر ردیف = **قیمت فروش کالا** (قبلاً میانگین × ۱٫۲ بود).
- [ ] فروش بیش از موجودی → خطای فارسی که نام کالا و هر دو مقدار را می‌گوید. **موجودی هیچ‌وقت منفی نمی‌شود.**
- [ ] فروش ۰٫۴ متر سیم پذیرفته می‌شود؛ ۰٫۴ عدد ال‌سی‌دی نه.
- [ ] فاکتوری که آخرین موجودی را فروخته (موجودی کالا ۰ شده)، با همان مقدار دوباره ویرایش و ذخیره شود → **رد نمی‌شود**؛ ویرایش اول سطرهای قبلی را برمی‌گرداند و بعد سطرهای جدید را برمی‌دارد.
- [ ] حذف فاکتور فروش موجودی را برمی‌گرداند.

## ۵. فاکتور تعمیر (۱۴.۷)

- [ ] پیش‌فاکتور (draft) با یک قطعه: **موجودی تغییر نمی‌کند**.
- [ ] صدور → قطعه **یک بار** کم می‌شود. پرداخت بعد از صدور، دوباره کم نمی‌کند.
- [ ] پیش‌فاکتور دیگری را مستقیم «پرداخت‌شده» کنید → قطعه یک بار کم می‌شود.
- [ ] لغو فاکتور صادرشده → قطعه برمی‌گردد.
- [ ] **برگرداندن صادرشده به پیش‌فاکتور رد می‌شود.**
- [ ] فاکتور صادرشده قابل ویرایش نیست؛ پیش‌فاکتور هست.

## ۶. سود و زیان (۱۴.۹)

- [ ] یک فروش ثبت کنید، بعد کالا را **گران‌تر** بخرید. سود آن فروش قبلی در گزارش سود **عوض نمی‌شود** (سود از بهای لحظه‌ی فروش حساب می‌شود، نه میانگین امروز).

## ۷. اصلاح موجودی — ADJ (۱۴.۱۴)

- [ ] منو «اصلاح موجودی» ← سند جدید. جهت «کاهش/افزایش» دو دکمه است.
- [ ] دلیل‌ها با جهت عوض می‌شوند: «خرابی، مفقودی، مصرف داخلی» فقط برای کاهش؛ «پیدا شده، برگشت از مصرف» فقط برای افزایش.
- [ ] دلیل «سایر» بدون توضیح رد می‌شود.
- [ ] برای افزایش، «بهای هر واحد» اختیاری است؛ خالی بماند، میانگین عوض نمی‌شود.
- [ ] کاهش بیش از موجودی رد می‌شود.
- [ ] شماره‌ها ADJ-0001، ADJ-0002… پشت سر هم. سند ویرایش و حذف ندارد.
- [ ] جزئیات سند: «کاهش ۱ عدد» / «افزایش ۲ عدد» با رنگ (نه علامت منفی جابه‌جا).

## ۸. انبارگردانی — CNT (۱۴.۱۵)

- [ ] منو «انبارگردانی» ← جدید: انبار (اگر دو تا هست)، دامنه (همه یا یک دسته)، تیک «شمارش کور».
- [ ] صفحه‌ی شمارش **روی گوشی** باز شود (۴۲۰px یا گوشی واقعی). هر ردیف با Enter یا خروج از فیلد **همان لحظه ذخیره می‌شود** (تیک سبز)، Enter به ردیف بعد می‌رود.
- [ ] جستجو و فیلتر «شمرده‌نشده / دارای اختلاف» کار می‌کنند. «افزودن کالا» کالای خارج از دامنه را اضافه می‌کند.
- [ ] **شمارش کور:** موجودی سیستم و اختلاف هیچ‌جا دیده نمی‌شود (در برگه‌ی چاپی هم نه).
- [ ] یک کالا را بشمارید، **بعد** یک فروش از همان کالا ثبت کنید، بعد «بررسی و اعمال»: هشدار نارنجی «۱ کالا پس از شمارش جابه‌جا شده» و دکمه‌ی اعمال تا تیک «بررسی کردم» غیرفعال است.
- [ ] اعمال: اختلاف نسبت به موجودی **لحظه‌ی شمارش** اعمال می‌شود و آن فروش حفظ می‌شود. کالاهای شمرده‌نشده دست نمی‌خورند.
- [ ] «برگه‌ی شمارش»: A4، به ترتیب قفسه، با جای امضا.
- [ ] لغو یک انبارگردانی دیگر: روی موجودی اثری ندارد و شماره‌اش می‌ماند.

## ۹. انتقال بین انبارها — TRF (۱۴.۱۶)

- [ ] فرم: از انبار پیش‌فرض به انبار دیگر. فهرست کالا **فقط کالاهای موجود در مبدأ** را با مقدارشان نشان می‌دهد.
- [ ] مقدار بیش از موجودی مبدأ → خطا قبل از ارسال (حتی اگر موجودی کل کافی باشد).
- [ ] دکمه‌ی ⇄ مبدأ و مقصد را جابه‌جا می‌کند و فهرست کالا را از انبار جدید می‌گیرد.
- [ ] بعد از ثبت: **موجودی کل و میانگین بهای کالا عوض نمی‌شود**؛ فقط موجودی هر انبار.
- [ ] جزئیات سند: «از انبار ← به انبار». ویرایش و حذف ندارد.

## ۱۰. صفحه‌ی کالا `/items/:id` (۱۴.۱۷، ۱۴.۱۸)

- [ ] از فهرست کالاها روی یک کالا بزنید → **صفحه** باز می‌شود (نه مودال). مسیر بالای صفحه: «انبار و کالاها › نام کالا»؛ زدن روی «انبار و کالاها» به فهرست برمی‌گردد.
- [ ] چهار تب: **نمای کلی · کاردکس · خرید و فروش · قیمت‌ها**. تب در آدرس می‌ماند (`?tab=kardex`)؛ رفرش روی همان تب باز می‌شود. دکمه‌ی back مرورگر از صفحه بیرون می‌رود، نه بین تب‌ها.
- [ ] کیبورد: روی تب انتخاب‌شده، فلش ← به تب بعدی می‌رود (راست‌به‌چپ)، Home/End به دو سر.
- [ ] نمای کلی: کارت وضعیت، خرید و فروش سریع (بعد از ثبت، عددها همان‌جا به‌روز می‌شوند)، اطلاعات، و با دو انبار جدول «موجودی در انبارها».
- [ ] ویرایش کالا از دکمه‌ی بالای صفحه؛ بعد از ذخیره صفحه به‌روز می‌شود.
- [ ] حذف کالایی که حرکتی داشته رد می‌شود با پیام.
- [ ] از داخل جزئیات یک فاکتور (خرید، فروش یا تعمیر) روی نام کالا بزنید → مودال‌ها **همه بسته می‌شوند** و صفحه‌ی کالا باز می‌شود.
- [ ] همین‌طور از گزارش موجودی، گزارش سود و زیان، و «تراکنش‌های انبار» داشبورد.
- [ ] آدرس کالای ناموجود (`/items/999999`) → «این کالا پیدا نشد» با دکمه‌ی بازگشت.

## ۱۱. کاردکس (۱۴.۱۹)

- [ ] همه‌ی حرکت‌ها، جدیدترین بالا: تاریخ سند، نوع (رنگی)، **شماره‌ی سند**، ورود، خروج، **مانده**، بها.
- [ ] مانده‌ی ردیف بالایی = موجودی فعلی کالا.
- [ ] فیلتر انبار: مانده‌ها مانده‌ی **همان انبار** می‌شوند.
- [ ] فیلتر تاریخ: فقط ردیف‌های بازه، ولی **مانده‌ی هر ردیف عوض نمی‌شود**. چهار کارت بالا: مانده ابتدای بازه، جمع ورود، جمع خروج، مانده پایان بازه.
- [ ] روی هر شماره‌ی سند بزنید: PUR/SAL/REP مودال فاکتور، ADJ و TRF مودال سند، CNT صفحه‌ی انبارگردانی.
- [ ] نگه داشتن ماوس روی ردیف: زمان ثبت و ثبت‌کننده.

## ۱۲. خرید و فروش، و قیمت‌ها (۱۴.۱۸، ۱۴.۲۰)

- [ ] تب «خرید و فروش»: سه کارت (خریده‌شده، فروخته‌شده، مصرف در تعمیر) و جدول همه‌ی فاکتورها؛ پیش‌فاکتور تعمیر و فاکتور لغوشده **در جدول هست ولی در جمع نه**. کلیک روی ردیف، فاکتور را باز می‌کند.
- [ ] تب «قیمت‌ها»: آخرین، کمترین، بیشترین قیمت خرید (هر کدام لینک به فاکتورش) و میانگین **وزنی** (۱۰ تا به ۱م و ۱ تا به ۲م ≈ ۱٬۰۹۰٬۹۰۹، نه ۱٬۵۰۰٬۰۰۰).
- [ ] «بهای موجودی فعلی» (میانگین متحرک) کنار قیمت فروش و «سود هر واحد» با درصد.
- [ ] کالایی که هرگز خریده نشده: پیام «هنوز با فاکتور خرید وارد نشده».

## ۱۳. گزارش‌ها (۱۴.۹، ۱۴.۲۱، ۱۴.۲۲)

**گزارش موجودی**

- [ ] فیلتر انبار (با دو انبار) فقط کالاهای موجود در آن انبار و ارزش همان انبار را نشان می‌دهد.
- [ ] «نمای انبارها»: یک ستون برای هر انبار فعال.
- [ ] «راکد» با بازه‌ی ۹۰ روز: کالاهایی که موجودی دارند و در این ۹۰ روز **فروخته یا در تعمیر مصرف نشده‌اند**، پرارزش‌ترین اول، با «آخرین فروش/مصرف» (یا «هرگز»). کارت بالا «ارزش موجودی راکد».
- [ ] «کم‌فروش»: کالاهایی که فروش داشته‌اند، به ترتیب «پوشش (روز)» = موجودی فعلی با این سرعت فروش چند روز دوام می‌آورد.
- [ ] خرید یا انتقال، کالا را از «راکد» بیرون **نمی‌آورد**؛ فقط فروش یا مصرف.

**گردش کالا** (منوی گزارش‌ها)

- [ ] پیش‌فرض: از اول ماه جاری شمسی تا امروز.
- [ ] هر ردیف: مانده اول + ثبت اولیه + خرید − فروش − مصرف تعمیر ± انتقال ± اصلاح و شمارش = **مانده پایان**. (یک ردیف را با دست جمع بزنید.)
- [ ] بازه‌ی «تا امروز»: مانده پایان = موجودی فعلی کالا.
- [ ] فیلتر انبار: عددهای همان انبار. ستون‌های انتقال فقط با دو انبار دیده می‌شوند.
- [ ] جستجو، دسته‌بندی، «فقط کالاهای دارای حرکت». کلیک روی ردیف → کاردکس آن کالا.

## ۱۴. دسترسی و جداسازی

- [ ] با اکانت **تکنیسین** وارد شوید: هیچ‌کدام از منوهای انبار، اسناد و گزارش‌ها نیست؛ باز کردن مستقیم `/stock-counts`، `/items/1` یا `/reports/movements` به صفحه‌ی دستگاه‌ها برمی‌گرداند (و API همان مسیرها ۴۰۳ می‌دهد).
- [ ] (اختیاری) اکانت دوم/کارگاه دوم: هیچ کالا، سند یا انباری از کارگاه اول دیده نمی‌شود.

## ۱۵. خروجی اکسل

- [ ] «خروجی اطلاعات» ← فایل اکسل: شیت‌های «موجودی انبارها»، «اصلاح موجودی»، «انبارگردانی»، «انتقال بین انبارها»، و ستون انبار در فاکتورها.

## ۱۶. گوشی و حالت تیره

- [ ] هر صفحه‌ی بالا را یک بار در عرض گوشی و یک بار در حالت تیره ببینید: متن ناخوانا، رنگ روشن مانده در حالت تیره، یا اسکرول افقی کل صفحه نباید باشد (جدول‌ها داخل کارت خودشان اسکرول می‌شوند — درست است).

## ۱۷. سلامت دیتابیس (بعد از همه‌ی تست‌ها)

هر سه عدد باید **۰** باشند:

```bash
docker compose exec postgres psql -U dofixo -d dofixo_dev -c "
SELECT
  (SELECT count(*) FROM items i
    WHERE current_stock <> COALESCE((SELECT sum(quantity) FROM item_stocks s WHERE s.item_id = i.id), 0)) AS item_vs_stocks,
  (SELECT count(*) FROM item_stocks s
    WHERE quantity <> COALESCE((SELECT sum(quantity) FROM inventory_transactions t
                                WHERE t.item_id = s.item_id AND t.warehouse_id = s.warehouse_id), 0)) AS stocks_vs_ledger,
  (SELECT count(*) FROM pg_policies WHERE schemaname = 'public') AS policies;"
```

- [ ] `item_vs_stocks = 0` و `stocks_vs_ledger = 0`.
- [ ] `policies = 42`.

## آنچه عمداً در این شاخه نیست

- **تأمین‌کننده و مرجوعی‌ها** (۱۴D)، **سفارش مجدد و رزرو** (۱۴E)، **حسابرسی و قفل دوره** (۱۴F) — فازهای بعد.
- تب «تغییرات» صفحه‌ی کالا — با حسابرسی (۱۴.۲۹) می‌آید.
- اسناد انبار (ADJ، CNT، TRF) ویرایش و حذف ندارند؛ اشتباه با یک سند دیگر اصلاح می‌شود. عمدی است: دفتر انبار فقط‌افزودنی است.
- غیرفعال کردن کالا از فرم کالا وجود ندارد.

## قبل از استقرار روی سرور

1. همه‌ی بندهای بالا تیک خورده یا مشکل‌هایشان رفع شده.
2. PR شاخه به master merge شده.
3. بکاپ پروداکشن (`ops/backup-database.sh`).
4. یک بار اجرای مهاجرت روی **کپی restore‌شده‌ی پروداکشن** طبق `ops/restore-database.md`، و اجرای کوئری بند ۱۷ روی آن.
5. build تازه‌ی هر دو image و اجرای سرویس `migrate` در `docker-compose.prod.yml`.
6. به کاربران خبر داده شود: فروش بیش از موجودی رد می‌شود، حذف خریدی که فروخته شده رد می‌شود، صادرشده به پیش‌فاکتور برنمی‌گردد، جزئیات کالا حالا یک صفحه است.
