# کارگاه دمو — `seed-demo-shop.mjs`

یک کارگاه ساختگی با چهار ماه کار، برای ارائه به مشتری و برای تست دستی:
**«موبایل‌کده آرتین»**، تعمیرگاه و فروشگاه لوازم موبایل.

داده از راه خود API وارد می‌شود، نه با SQL. پس هر عددی که در دمو دیده
می‌شود — موجودی، میانگین بها، سود، شماره‌ی فاکتورها، کاردکس — همان چیزی است
که منطق واقعی برنامه حساب کرده است، و اگر چیزی در دمو غلط باشد، در برنامه
غلط است.

## چه چیزهایی ساخته می‌شود

| بخش | محتوا |
|---|---|
| تنظیمات | نام کارگاه، تلفن، آدرس، شرایط ضمانت؛ نام مدیر کل «آرتین رحمانی» |
| پرسنل | ۱ مدیر و ۳ تعمیرکار، با رمز همان حساب دمو |
| انبار | «انبار اصلی» + «ویترین فروشگاه» (پس انتخابگر انبار و منوی انتقال دیده می‌شوند) |
| کالا | ۲۵ کالا در ۵ دسته؛ شامل کالای کسری (سیم به **متر**، خمیر سیلیکون به **گرم**) و یک واحد سفارشی («حلقه») |
| خرید | ۱۴ فاکتور خرید در چهار ماه با قیمت‌های متغیر (تا میانگین بها و تب «قیمت‌ها» معنا داشته باشند) |
| انتقال | ۳ سند انتقال از انبار اصلی به ویترین |
| مشتری | ۴۰ مشتری، دو نفر با یادداشت داخلی |
| دستگاه | ۶۰ دستگاه در همه‌ی وضعیت‌ها، با تعمیرکار؛ قدیمی‌ها تحویل‌شده، تازه‌ها در کارگاه |
| فاکتور تعمیر | ~۳۳ صادرشده/پرداخت‌شده با پرداخت‌های جدا، چند پیش‌فاکتور؛ قطعه از انبار مصرف می‌شود |
| فاکتور فروش | ~۳۴ فاکتور، بیشتر از ویترین، بعضی نسیه |
| اصلاح موجودی | ۲ سند (شکستگی، پیدا شدن) |
| انبارگردانی | ۱ سند اعمال‌شده (دسته‌ی باتری، با دو اختلاف) + ۱ شمارش کور نیمه‌کاره روی ویترین |

هیچ پیامکی فرستاده نمی‌شود (`send_sms: false` و کیف پول پیامک خالی). شماره‌ی
مشتری‌ها `0912000000x`… ساختگی است.

داده تکرارپذیر است: هر بار اجرا روی یک کارگاه خالی همان کالاها و همان
مشتری‌ها را می‌سازد؛ تاریخ‌ها نسبت به امروز حساب می‌شوند تا داشبورد همیشه
«تازه» باشد.

## ایمنی

- اسکریپت **فقط روی کارگاه خالی** می‌نویسد. قبل از هر چیز چک می‌کند کارگاه
  هیچ کالا، مشتری، دستگاه، یا فاکتور خرید و فروشی نداشته باشد؛ اگر داشت
  بدون نوشتن چیزی خارج می‌شود (کد خروج ۲). پس با اشتباه زدن شماره‌ی یک
  مشتری واقعی، داده‌ی او خراب نمی‌شود.
- قبل از نوشتن، نام کارگاه و حساب را نشان می‌دهد و تأیید (`y`) می‌خواهد.
  `--yes` این سؤال را حذف می‌کند.
- هیچ چیزی را پاک نمی‌کند.

## اجرا روی لوکال

پیش‌نیاز: Node 18 یا بالاتر (هیچ پکیجی لازم ندارد)، و بک‌اند در حال اجرا.

**۱. یک حساب خالی بسازید** — یکی از این دو:

- از صفحه‌ی ثبت‌نام اپ (`http://localhost:5173`) با یک شماره‌ی تازه. کد
  تأیید پیامکی است، پس فقط وقتی کار می‌کند که کلید sms.ir در `.env` لوکال
  باشد.
- یا دیتابیس لوکال را از نو بسازید؛ `prisma/seed.ts` یک کارگاه خالی با
  `SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD` می‌سازد:

  ```bash
  cd backend
  pnpm prisma migrate reset   # ⚠️ کل دیتابیس لوکال پاک می‌شود
  pnpm seed                   # کارگاه خالی با SEED_ADMIN_USERNAME
  ```

**۲. اسکریپت را اجرا کنید** (از ریشه‌ی ریپو):

```bash
DEMO_PHONE=09xxxxxxxxx DEMO_PASSWORD='رمز حساب' node ops/demo/seed-demo-shop.mjs
```

آدرس پیش‌فرض API `http://localhost:5001/api` است. اجرا حدود ۱۰ ثانیه و
~۳۷۵ درخواست طول می‌کشد. در پایان شماره‌ی پرسنل چاپ می‌شود؛ با هر کدام و
همان رمز می‌شود وارد شد (مثلاً با تعمیرکار، برای دیدن نمای محدودش).

## اجرا روی سرور (بعد از دیپلوی)

اسکریپت روی **لپ‌تاپ خودتان** اجرا می‌شود و با HTTPS به سرور وصل می‌شود؛
لازم نیست روی سرور چیزی نصب یا کپی شود.

1. در `https://app.dofixo.ir` با یک شماره‌ی واقعی که پیامک را دریافت می‌کنید
   ثبت‌نام کنید (مثلاً یک سیم‌کارت دوم). کارگاه تازه یک ماه آزمایشی رایگان
   دارد که برای ارائه کافی است.
2. اجرا:

   ```bash
   DOFIXO_API=https://app.dofixo.ir/api \
   DEMO_PHONE=09xxxxxxxxx DEMO_PASSWORD='رمز حساب' \
   node ops/demo/seed-demo-shop.mjs
   ```

3. وارد شوید و داشبورد را ببینید.

رمز را در دستور بنویسید، نه در فایلی که کامیت می‌شود.

## اگر وسط کار متوقف شد

- **سقف درخواست (429):** API در هر ۱۵ دقیقه ۱۰۰۰ درخواست از یک IP
  می‌پذیرد. اسکریپت خودش صبر می‌کند و ادامه می‌دهد؛ فقط دو بار پشت سر هم
  روی یک IP اجرا نکنید.
- **قطع شبکه یا خطای دیگر:** کارگاه نیمه‌پر می‌ماند و اجرای دوباره (به‌درستی)
  رد می‌شود. یک حساب تازه بسازید و دوباره اجرا کنید؛ کارگاه نیمه‌کاره بعد از
  پایان دوره‌ی آزمایشی، مثل هر کارگاه منقضی‌شده‌ی دیگری، با کران اشتراک
  (`ops/subscription-cron.md`) پاک می‌شود.
